# 静态演示

线上演示是 GitHub Pages 上的静态站点，不连接造印机后端，也不包含万物有声的模态数据。

预期地址（合并到 `main` 且 Pages 工作流成功之后）：

| 页面 | 地址 |
|---|---|
| 首页 | https://zicheng-yu.github.io/wanwuyin/ |
| 八枚合影 | https://zicheng-yu.github.io/wanwuyin/seal.html?view=set |
| 三种印材 | https://zicheng-yu.github.io/wanwuyin/seal.html?view=set&materials=1 |
| 单枚三联图 | https://zicheng-yu.github.io/wanwuyin/seal.html?seal=elephant |

| 造印机 | https://zicheng-yu.github.io/wanwuyin/maker.html |

`seal=` 还可以换成 blue_whale、trex、shark、ant、saturn、volcano、yongzhong。造印机页面在生产构建里默认只摸已经备好的印。在线铸造仍要在本机运行 `pipeline/scripts/serve_seals.py`，密钥不进前端。

窄屏（手机竖屏）上，八枚合影改成两列，避免四列被裁出画面。宽屏仍是原来的两排四列。

## 构建

```bash
cd web
npm ci
npm run build    # 输出 web/dist，资源前缀是 /wanwuyin/
```

本地 `npx vite` 仍从站点根目录提供页面，包括万物有声的 `index.html` 和 `listen.html`。落地页在开发时是 `home.html`，生产构建把它写成 `dist/index.html`。`vite build` 不再打包万物有声的两个入口。

## 为什么 dist 里没有万物有声

Vite 会把 `web/public` 整份复制进 `dist`，其中 `objects/*/modes.bin` 很大（`cup` 一个就约 87 MB）。这些文件只给叩物沙盒和听触页用，合影、单枚印和造印机都不读它们。

`web/vite.config.ts` 里的 `wanwuyin-static` 插件在复制完成之后删掉 dist 里没有被印章页面引用的物体文件，以及声学用的 `materials.json`。源文件留在 `web/public`，本地开发不受影响。`npm run build` 末尾的 `tools/check-dist.mjs` 会拒绝 dist 里出现 `modes.bin`、听触物体，或超过 2 MB 的 GLB。

甬钟有两份模型：`objects/yongzhong/model.glb` 保持原始大小，给万物有声对齐 `modes.bin` 的顶点；印章页用压缩后的 `objects/yongzhong/seal.glb`。部署包只带走后者。

## 重新压缩模型

八枚印和大象三种印材、甬钟四视图，都用 meshopt 加 1024 WebP：

```bash
cd web
node tools/slim-glb.mjs public/objects/elephant/model.glb public/objects/elephant/model.glb
```

命令等同于 `npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress webp --texture-size 1024`。网页用同一个 `GLTFLoader`，并 `setMeshoptDecoder`。不要对已经压过的文件再跑一遍。

八枚印的原始 GLB 在 Release `snapshot-2026-11-11`。大象三材和 `yongzhong_mv` 是之后加的，完整文件在压缩这次提交之前的 git 历史里。仓库里不再放第二份全尺寸副本。
